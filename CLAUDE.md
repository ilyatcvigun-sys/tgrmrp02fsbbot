# Telegram-бот конференции RM-RP 02 (ФСБ)

Бот управления игровой конференцией на сервере Radmir CRMP / Hassle Online.
Ведёт состав, ранги, отделы, жалобы, выговоры, предупреждения и развлекательные
модули (кубы, дуэли, статьи УК, пары).

Интерфейс бота **полностью на русском**. Комментарии в коде тоже на русском —
придерживайся этого.

---

## Стек и запуск

- Python, `python-telegram-bot` v20+ (asyncio)
- **PostgreSQL** (переехали с SQLite, см. раздел ниже)
- Хостинг: **bothost**, панель без терминала. Деплой = залить файлы через
  файловый менеджер и нажать «Перезапустить».

## Mini App «Личное дело»

Telegram Web App поверх той же PostgreSQL. Живёт в `webapp.py` — самостоятельный
модуль, **не импортирует** `bot.py` напрямую (у главного файла нет расширения
`.py`, обычный `import` с ним не работает). Вместо этого `bot.py` вызывает
`webapp.create_app(bot_token=..., db_file=..., sqlite3_module=..., ranks=...,
admin_ids=..., get_departments=...)` — все зависимости пробрасываются
параметрами.

**Как запускается:** Flask-сервер поднимается в фоновом потоке
(`threading.Thread(target=run_webapp, daemon=True)`) внутри `main()`, **после**
`init_database()` — использует уже готовый пул соединений `db_pg` (тот же
процесс, тот же пул, отдельный поток). Сам бот как работал на long polling,
так и работает — Flask не заменяет и не блокирует его.

**Хостинг (bothost):**
- Нужен тариф **не ниже «Базовый»** — на бесплатном домен/webhook недоступны.
- В настройках бота на панели включить тумблер **«Использовать домен»** —
  bothost выдаёт HTTPS-поддомен и кладёт его в переменную окружения `DOMAIN`.
- Порт веб-сервера — из переменной окружения `PORT` (её тоже выставляет
  bothost). Если `PORT` не задана — `run_webapp()` тихо не запускает сервер
  (лог `webapp: переменная PORT не задана`), бот при этом продолжает работать.
- Кнопка «📇 Личное дело» в `/start` показывается **только если** `DOMAIN`
  задан (`_mini_app_url()`) — без домена ссылка была бы нерабочей.

**Аутентификация:** Telegram Web App SDK кладёт в `window.Telegram.WebApp.initData`
подписанный пакет с данными пользователя. Фронтенд шлёт его в заголовке
`Telegram-Init-Data` на каждый запрос к `/api/...`, бэкенд проверяет подпись
HMAC-SHA256 на `BOT_TOKEN` (`webapp.validate_init_data`) — так бэкенд узнаёт
`user_id` без отдельного логина.

**Права:** свою карточку (без пометок) видит любой зарегистрированный
пользователь. Полную карточку (с разделом «Особые отметки» из `user_notes`),
чужие карточки и редактирование — только ранг 5+, спецдопуск или главный
админ (`ADMIN_IDS`), см. `_is_staff()` внутри `create_app`.

**Если понадобится Menu Button** (постоянная кнопка слева от поля ввода,
вместо/вместе с кнопкой в `/start`) — это настраивается вручную через
@BotFather (`/mybots` → бот → Bot Settings → Menu Button → указать
`https://<DOMAIN>/`), в коде это не хранится.

## Ранги

`RANKS` — словарь 0–7. Ключевые пороги:

- **0** — гость
- **4** — подполковник: жалобы, теги, пометки, выговоры, женитьба
- **5** — полковник: варны, муты, кики, баны, награды, смена ранга/отдела
- **6** — генерал: регистрация пользователей, жетоны
- **7** — следящий за ФСБ: спецдопуск

Поверх рангов две отдельные системы:

- **Спецдоступ** (`has_special_access`) — флаг в `users.special_access`
- **Индивидуальные гранты** (`command_grants`) — точечная выдача прав на
  конкретную команду. Множество `GRANTABLE_COMMANDS` намеренно **не включает**
  команды уровня «разработчик» (удаление юзеров, бэкап, спецдопуск, глобальный
  ЧС) — защита от эскалации прав. Не добавляй их туда.

Проверка прав: `has_permission(user_id, 'ключ_права', 'имя_команды')`.

## Форум-топики: главная ловушка проекта

Конференция — супергруппа **с топиками**. В таких чатах у *каждого* сообщения
автоматически есть `reply_to_message`, указывающий на сообщение-стартер темы,
даже если пользователь никому не отвечал.

Из-за этого наивная проверка `if update.message.reply_to_message:` заставляла
команды применяться к автору первого сообщения топика. Симптом был такой:
пишешь `/asetrank @borchrus 4` — ранг меняется у создателя темы.

**Всегда используй `_is_real_reply(message)`** вместо прямой проверки
`reply_to_message`. Функция отсеивает стартеры топиков и служебные сообщения
`forum_topic_created`. `extract_user_id` уже использует её внутри.

Отправка в конкретный топик — параметр `message_thread_id`.

## PostgreSQL и слой совместимости

Бот исторически написан под `sqlite3`: 158 мест `sqlite3.connect`, 306 запросов
с плейсхолдерами `?`. Вместо переписывания всего используется слой
совместимости.

**`bot.py` строка 12:**

```python
import db_pg as sqlite3
```

`db_pg.py` эмулирует API `sqlite3` поверх `psycopg3` и переводит SQL на лету:

| SQLite | PostgreSQL |
|---|---|
| `?` | `%s` |
| `"строка"` | `'строка'` (в PG двойные кавычки = имя колонки) |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGSERIAL PRIMARY KEY` |
| `INTEGER` | `BIGINT` — Telegram ID не влезает в `INTEGER` PG |
| `cursor.lastrowid` | дописывается `RETURNING id` |
| `sqlite3.Row` | гибридные строки: работают и `row['nick']`, и `row[0]` |

Ошибки psycopg преобразуются обратно в `sqlite3.OperationalError` /
`sqlite3.IntegrityError`, чтобы существующие `except` работали.

### Правила, которые легко нарушить

**1. Каждый запрос обёрнут в SAVEPOINT.** В PostgreSQL упавший запрос переводит
транзакцию в состояние aborted и всё последующее падает до отката. В SQLite
такого нет, а бот на этом построен (`try: ALTER TABLE … except: pass`).
Savepoint откатывает только упавший запрос.

**2. Служебные команды savepoint идут по ОТДЕЛЬНОМУ курсору.** Если выполнять
`RELEASE SAVEPOINT` на основном — он затрёт результат `SELECT`, и `fetchone()`
вернёт `None`. Уже ловили.

**4. Авто-prepared statements выключены** (`prepare_threshold=None` в пуле).
С ними psycopg в pipeline после упавшего запроса терял подготовленный
SAVEPOINT и следующий запрос падал с `prepared statement "_pg3_N" does not
exist` — ронял старт бота в `init_database`. Не включай обратно.

**3. `ADD COLUMN` НЕ переписывается в `ADD COLUMN IF NOT EXISTS`.** Бот
использует идиому «попробовать добавить колонку, при неудаче пропустить разовый
бэкфилл». Если `ALTER` перестанет падать, бэкфилл выполнится при каждом запуске
и затрёт пользовательские настройки (ловили на видимости отделов в `/find`).

### Портируемость SQL

PostgreSQL строже SQLite. Уже исправлено, не сломай обратно:

- `MAX(a, b)` → **`GREATEST(a, b)`**. В SQLite скалярная функция, в PG агрегат.
  Ронял каждый выстрел в дуэли.
- В `GROUP BY` должны быть **все** неагрегированные колонки.
- В `HAVING` **нельзя ссылаться на псевдоним** из `SELECT` — повторяй выражение.

### Автоперенос

`migrate_to_pg.auto_migrate_if_needed()` вызывается из `main()`. Если в PG пусто,
а `conference.db` на месте — переносит данные и логирует отчёт. Идемпотентно:
видит заполненную базу и молчит.

## Схема БД (28 таблиц в каждой конфе + глобальные `public.g_*`)

`users` `warnings` `awards` `reports` `gban` `departments` `department_groups`
`polls` `poll_votes` `command_grants` `change_requests` `audit_log`
`article_history` `duels` `cube_games` `changelogs` `idea_polls` `ideas`
`topic_violations` `punishments` `marriages` `user_notes`
`rank_names` `user_departments` `reg_fields` `user_fields` `points_log`
`user_comments`

Заметки по данным:

- **Время хранится строками** `'YYYY-MM-DD HH:MM:SS'` и сравнивается
  лексикографически. Работает, менять на `TIMESTAMPTZ` — отдельная большая
  задача, не трогай попутно.
- `users.warns` — строка `"<преды>/<выговоры>"`, не число. Лимиты —
  `WARN_VERBAL_MAX` (2) и `WARN_WRITTEN_MAX` (3, последний = автокик).
  **Показывается наоборот — сначала выговоры, потом преды** («1/3 0/2»):
  всегда через `warn_counts_text()`, не выводи `warns` напрямую.
  `/warn @user [1|2] причина` и `/unwarn @user [1|2] причина`: 1 — пред,
  2 — выговор (`_warn_kind_arg`, «выг» = 2). `/warns` — все с варнами (5+),
  `/mywarns` — свои, `/warnlist [user]` — вся история со снятыми/истёкшими. Объявление о
  выдаче — `warn_announce_text()` («ExBot » Пользователь … получил …», подпись —
  `WARN_ANNOUNCE_PREFIX`, всегда «ExBot», не имя бота).
- **Все объявления о наказаниях и их снятии** (warn/unwarn/unwarnall, mute/unmute,
  kick, ban/unban и те же действия через текстовые триггеры) — в формате
  `exbot_text(строка, warns=…, reason=…)` и через `announce_punishment()`:
  в тот чат, где выполнили команду, + в ЛС пользователю. При кике ЛС уходит
  **до** `disconnect_user_from_bot` (отключённым `notify_user` не пишет).
  ЧС (`/gban`) — исключение: пользователю ничего не приходит, а запись о
  выдаче/снятии уходит в лог-группу `PM_LOG_CHAT_ID` (`_log_gban`).
  Аудио-заставки перед киком/баном («…что-то натворил») удалены по решению
  владельца — не возвращай.
- `/get` (бывш. `/who`) — карточка в стиле ExBot: разделы «Информация о
  конференции / сообщениях / Профиль / Наказания и заслуги / Время в беседе»,
  HTML. `users.msg_count` и `last_msg_at` считает `track_username` (только
  сообщения в чате конфы, с момента внедрения). Время в беседе — из
  `service_periods`: точное `started_at`, для старых записей — дата `hired_at`
  (её формат `дд.мм.гггг` не менять — правится из Mini App).
- `user_comments` — **скрытые комментарии** (`/addcomment`, `/comments`,
  `/delcomment`): видит и пишет только главный админ и спецдопуск
  (`_can_see_comments`), грантом не выдаются. Не путать с `user_notes`
  (пометки с 4 ранга, видны в Mini App). Правила: ответы только через
  `_private_reply()` (в группе команда удаляется, ответ уходит в ЛС); в `/get`
  раздел показывается только спецдопуску и только в «безопасном» чате —
  ЛС или лог-группа `PM_LOG_CHAT_ID` (`_is_secure_chat`), там же команды
  отвечают прямо в чат; в `audit_log` пишется
  факт без текста. Не выводи их больше нигде.
- `command_grants` — единственная таблица **без колонки `id`** (составной ключ).
  Слой совместимости это учитывает при эмуляции `lastrowid`.
- **Голосования:** в топике конфы цифры НЕ показываются — только «идёт» и
  итог («✅ Прошёл / ❌ Не прошёл», у `multi` — выигравший вариант).
  Количество голосов — в `/poll_info` и `/polls` только главному админу и
  спецдопуску (`_can_see_poll_counts`). Срок: `/poll_create [срок] …`,
  `/poll_multi [срок] …` → `polls.ends_at`, закрывает `poll_deadline_job`
  (раз в минуту, `per_conf_job`). Закрытие — всегда через `finish_poll()`.
- `points_log` — поинты (`/point`, с 4 ранга, ключ права `points`, можно
  минус), баланс = сумма. `/pointlist`, `/points` — всем.
- `polls.poll_type`: `'candidate'` — да/нет/воздержусь (`/poll_create`),
  `'multi'` — вопрос с вариантами (`/poll_multi Вопрос | А | Б`), варианты в
  `polls.options` (JSON), голос в `poll_votes.vote` = `'o<индекс>'`, счётчики
  считаются из `poll_votes` (`get_poll_by_id()['counts']`).
- `punishments` — публикации о выговорах. Реальный варн **не выдают**, только
  объявление.

## Соглашения по интерфейсу

**Везде показывай `nick` (игровой ник), а не `callsign` (позывной).**
Это отдельно правилось по всему коду. Исключения — места, где намеренно
показаны оба: собственный профиль, карточки `/ablock`, `/akick`, `/aban`
(формат `Ник (Позывной)`).

**Позывной и жетон показываются, только если они есть в регистрации конфы**
(`/regfields`). Не выводи `callsign`/`token` напрямую — используй
`with_callsign(nick, cs)` для «Ник (Позывной)», `cs_line(...)` / `tk_line(...)`
для строк профиля (возвращают строку с `\n` или пустую), флаги —
`callsign_shown()` / `token_shown()`. `/register` и `/forcereg` сами ждут
меньше аргументов, если поле выключено.

Оформление сообщений:

```
🎯 ЗАГОЛОВОК
━━━━━━━━━━━━━━━━━
👤 Поле: значение
━━━━━━━━━━━━━━━━━
```

Разделитель — именно `━━━━━━━━━━━━━━━━━`. Эмодзи в начале строк, лаконичный тон.

Время — МСК через `now_msk()` / `now_msk_str()`, зона `Europe/Moscow` (zoneinfo).
Длительности — `parse_duration()`, понимает `30m`, `30м`, `2ч`, `7 дней`,
`1 неделя`, и голое число как минуты.

## Игровые модули и топик активностей

Кубы, «моя статья» и пары работают **только в `GAMES_ALLOWED_TOPIC_ID`**.
В других топиках конференции срабатывает `_handle_topic_violation` —
накопительные санкции за 7 дней:

- 1–2 нарушения: удалить сообщение + замечание
- 3-е: + мут 5 минут
- 4+: + мут 15 минут + **реальный варн** через `add_warning`

Антифлуд: замечание не чаще раза в минуту на пользователя. В ЛС ограничений нет.

Проверка — `_is_in_games_topic(update)`. Возвращает `True` вне конференции
(в ЛС играть можно свободно).

## Мультиконференции — критично

Бот обслуживает **несколько конференций**. У каждой — своя схема PostgreSQL с
полным набором таблиц: пользователи, ранги, отделы, жалобы, варны, гранты — всё
своё, между конфами ничего не переносится. Основная конфа (ФСБ) — схема
`public` (исторические данные на месте), остальные — `conf_<id>`.

**Как выбирается конфа.** `conf_router` (группа **−100**, `TypeHandler`) на каждый
апдейт: в группе — по ID чата (незнакомый чат → основная), в ЛС — активная конфа
пользователя (`public.g_active_conf`, переключение `/conf`). `db_pg` сам ставит
`search_path` на схему текущей конфы (contextvar), поэтому обычный код с
`sqlite3.connect(DB_FILE)` менять не нужно.

**Правила:**
- `CONFERENCE_CHAT_ID` и `*_TOPIC_ID` — только засев реестра для основной конфы.
  В коде — `conf_chat()` и `conf_topic('verdict'|'games'|'poll')`. Топик `None`
  = общий чат (для игр — «играть везде»).
- Глобальные таблицы — в `public` с префиксом `g_`, **всегда** пишутся как
  `public.g_…` (в конфах `search_path` = только их схема): `g_conferences`
  (реестр), `g_active_conf`, `g_link_groups` (связки), `g_msg_conf`.
- Работа в другой конфе — `with using_conf(conf):`. Периодические задачи
  JobQueue оборачивай в `per_conf_job(...)`, отложенные `run_once` — в
  `conf_bound(...)`, иначе они выполнятся в основной конфе.
- Кэши в памяти — по схеме (`blocked_users` = `_PerConfSet`, `RANKS` = `_ConfRanks`).
- Кик/бан — в `_action_chat_id(update)`, проверка «мы в конфе» — `_in_conf_chat(update)`.
- `ConfTrackingBot` запоминает, из какой конфы ушло сообщение с inline-кнопками
  в ЛС (`g_msg_conf`); нажатие обрабатывается в той конфе и делает её активной.
- Новая конфа: `/confnew` в её чате (главный админ) создаёт схему и таблицы
  через `init_database()`. Стартовые отделы `DEPARTMENTS_INITIAL` сеются
  **только** в основной конфе.
- Mini App «Личное дело» — **только основная конфа** (кнопка в `/start` только там).

**Регистрация:** сначала выбор конфы (`REG_CONF`), в списке только конфы с
открытой регистрацией, где человек реально состоит в чате (`get_chat_member`).
Дальше вопросы из `reg_fields` этой конфы по очереди (`REG_FIELD`,
`reg_field_answer`), настройка — `/regfields`. Встроенные поля `nick`/`callsign`
пишутся в `users` (можно выключить, нельзя удалить; ник выключен → имя из
Telegram, позывной → `'—'`), свои — в `user_fields` и выводятся в профилях
через `extra_fields_text()`. Необязательное поле пропускается ответом «-».
Жетоны — тоже в `/regfields` (`token on|off`, `token format <префикс|-> <цифр>`),
настройки в `public.g_conferences` (`token_enabled/prefix/digits`, по умолчанию
`52` + 4 цифры), читать через `token_settings()`. Жетон выключен → в
`users.token` пишется NULL (колонка без NOT NULL), `add_user` и
`get_user_data` отдают `'—'`.

**Ранги:** уровни 0–7 и права по ним общие, названия — свои в каждой конфе
(`rank_names`, `/rankname`). `DEFAULT_RANKS` — названия по умолчанию.

**Отделы:** основной — `users.department`, дополнительные — `user_departments`
(`/adddept`, `/deldept`). Фильтр «состоит в отделе» — `IN_DEPT_SQL` (параметр
дважды). В `get_user_data` есть `departments` и `departments_str` — для показа.
`/find` листается по 10 человек (`findpg:<стр>`).

**Связки (`/global create|add|remove|info`, главный админ):** конфы с одним
`link_group` делят ЧС (`add_gban`/`remove_gban` пишут во все, при `add` ЧС
объединяется) и глобальные команды `/gwarn /gunwarn /gmute /gunmute /gkick
/gunban /gblock /gunblock` (`make_global_command`: локальный хэндлер в каждой
конфе связки, где цель зарегистрирована; права — свои в каждой конфе).
`/gbinfo` — сводка по человеку во всех беседах. `/pm` ищет получателя во
всех конфах, если в текущей не нашёл.

`/tagall`: гиперссылки и форматирование сохраняются (`message.text_html`),
`[текст](https://…)` тоже становится ссылкой; ответ на сообщение с файлом —
вложение уходит в чат и в ЛС (`copy_message`).

## Справка `/ahelp`

Построена на реестре `HELP_SECTIONS` — единый источник правды для меню и
содержимого разделов. Меню на inline-кнопках, разделы тематические, сообщение
перерисовывается на месте.

**Добавил команду — допиши строку в реестр:**

```python
("имя_команды", "<аргументы>", "описание", уровень)
```

где уровень: `0` — все, `4`/`5`/`6`/`7` — минимальный ранг, `'spec'` —
спецдоступ, `'main'` — главный админ. Команда сама появится в нужном разделе
с учётом прав.

Проверка покрытия — сверь список из словарей `commands` и `no_prefix` в `main()`
с реестром. На момент написания: 145 команд. `/who`
переименована в `/get` (гранты на `who` переносятся при старте), пропущенных нет.

## Что уже пробовали и убрали

Не предлагай заново — это осознанные решения владельца:

- **Еженедельный автоопрос идей** — удалён, раздражал.
- **Автопредложение changelog при старте** — удалено, заменено на уведомление
  «бот запущен» (`startup_notify_job`, через 5 секунд после старта, шлётся и в
  лог-группу, и в ЛС админу).
- **Публичное объявление о гбане с аудио** — убрано, теперь ЧС выдаётся тихо
  (жертва не получает вообще никаких уведомлений). Подтверждение с причиной —
  вызвавшему, ответом в тот же чат, где выполнена команда (не форсируется в ЛС).
- **SAMP-запрос статуса сервера** — удалён.
- **AI-анализ настроения чата** (`/mood`, `/mooddebug`, автопост раз в 6 часов
  через OpenRouter) — вырезан целиком: работал плохо, оказался не нужен.
  Вместе с ним ушли `track_message` (буфер сообщений конфы), зависимость
  `openai` и константы `OPENROUTER_*`. Не предлагай возвращать или заменять
  другим AI-анализом настроения.
